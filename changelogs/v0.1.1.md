# Retro PC 0.1.1 — a damaged CD or kernel can no longer crash it

Found by fuzzing, in the part of Retro PC that reads your files. The same code runs inside HavenDOS (Apps > Retro PC), so HavenDOS 0.9.7.7 takes the fix too.

> **Not tested on a real machine.** Built and tested on the build machine.

## Fixed

- **A damaged `.ISO` could crash Retro PC.**
  - The CD reader trusted each directory entry's name length, so a name longer than its entry read past the end of the image.
  - A directory placed far enough into the disc wrapped its position around 32 bits and was read from the wrong place.
  - Now every entry has to fit inside the image, and positions are worked out in 64 bits.
- **A damaged kernel could crash Retro PC.** The kernel on a CD says how big its parts are, and those sizes were believed:
  - a part whose file size was bigger than its memory size made Retro PC clear almost 4 GB;
  - offsets near 4 GB wrapped past the checks;
  - a Multiboot header at the very end of the file was read past the end.

  Now each size is checked against the file and against memory before anything is copied. A kernel that fails says so: "the kernel's program headers are damaged".

## Tests

- **test_fuzz** (new, 12 checks), built with AddressSanitizer:
  - each of the bugs above, built exactly;
  - 20,000 mutated CDs and `grub.cfg` files, 1,500 mutated kernels loaded and run, and 150 runs of random code on the 386, from a fixed seed so a failure repeats.

  Against 0.1.0 it stops at the first CD check with an out-of-bounds read.
- Longer runs while it was written: 2 million CDs, 20,000 kernels, 3,000 runs of random 386 code and 20,000 random 8086 boot sectors, all clean.
- The HID report descriptor parser and the DER/PEM key reader that HavenDOS uses were fuzzed too, 20 million and 2 million inputs, and are clean.
